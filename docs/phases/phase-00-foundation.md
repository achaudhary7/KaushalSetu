## Objective

Stand up the repository, the toolchain and the documentation system so that every later phase has
somewhere obvious to put its work, and so no context is ever lost between sessions. Nothing
user-facing ships in this phase beyond a styled placeholder — that is correct and intentional.

## In scope

- Next.js 15 App Router + TypeScript scaffold
- Tailwind CSS v4 with the token file stubbed
- ESLint, Prettier, TypeScript strict mode, path aliases
- Folder architecture for all sixteen phases
- Environment variable handling with runtime validation
- Git repository with correct ignores and a first commit
- The complete documentation set and the phase-tracking system

## Out of scope

- Any component beyond a placeholder (Phase 1)
- Any page content (Phase 2)
- The database (Phase 3)

## Acceptance criteria

1. `npm run dev` starts and serves a styled page at `http://localhost:3000` with no console errors.
2. `npm run build` completes with no errors and no type errors.
3. `npm run lint` reports zero problems.
4. Deleting a required variable from `.env` makes the app fail at boot with a clear message naming
   the variable — not a mystery runtime crash later.
5. Every file listed in `CONTEXT.md` §7 exists.
6. A new reader can open `CONTEXT.md` and know what to do next without asking anyone.

## Key files this phase creates

```
src/config/site.ts          Product identity, navigation, contact — imported everywhere
src/lib/env.ts              Validated environment access
src/app/layout.tsx          Root layout, fonts, theme, base metadata
src/styles/globals.css      Tailwind entry + design token declarations (stub)
.env.example                The environment contract
```

## Notes & risks

- **Do not skip `src/config/site.ts`.** Hard-coding the product name in 40 files is the single most
  common way a project like this becomes painful to rename or white-label later.
- Tailwind v4 moves configuration into CSS (`@theme`). If a v3-style `tailwind.config.ts` is
  generated by the scaffold, that is fine to keep for plugin registration, but tokens live in CSS.
- Keep the placeholder homepage genuinely minimal. The temptation to start designing here is strong;
  resist it, because Phase 1 will replace it entirely.
